# SaySo: плашка v2 (анимация, Acrylic, рамка) для 0.1.3

Дополнение к `2026-10-14-sayso-design.md` (§8 плашка). Решения владельца (2026-10-15):
1. Плашка появляется плавной анимацией в стиле Apple, с инерцией: выезжает из-под нижнего края экрана. По мере выезда она превращается из круга в капсулу.
2. У столбиков уровня углы скруглены по максимуму: радиус равен половине ширины.
3. Материал капсулы — настоящий Windows Acrylic, как в WinUI, через Windows Composition. Подтверждено: рост памяти демона в простое не более ~3–8 МБ. Его нужно измерить и по возможности свести к нулю.
4. Рамка как у окон Windows 11: 1 физический пиксель, полупрозрачная.

## 1. Архитектура
- **Вывод.** Плашка остаётся отдельным окном верхнего уровня демона: `WS_POPUP`, `WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE | WS_EX_TRANSPARENT`. Рисуется оно через Windows.UI.Composition (`DesktopWindowTarget`), а не через `UpdateLayeredWindow`, и создаётся с `WS_EX_NOREDIRECTIONBITMAP`. Фокус не берёт, щелчки пропускает.
- **Без WinUI.** XAML и Microsoft.UI.* в демон не загружаются, проверка `xaml=0` остаётся. Используются только системные Windows.UI.Composition, CoreMessaging, dcomp, d3d11/d2d1/dwrite. Вызовы — через проекции Windows SDK (CsWinRT, совместимо с NativeAOT) и ручной COM-interop там, где проекций нет: `ICompositorDesktopInterop`, `ICompositorInterop`, `ICompositionDrawingSurfaceInterop`.
- **Жизненный цикл ради памяти.**
  - Компоновщик, `DispatcherQueueController` (на главном потоке), устройство D3D11/D2D и визуалы создаются лениво, при первом показе в сессии. Плашка показывается через 150 мс после нажатия, поэтому создание можно начать в момент нажатия.
  - После анимации скрытия всё освобождается (Close/Dispose, Release), затем сработает `MemoryTrimmer`.
  - Цель: private-память демона в простое после диктовки та же, что в 0.1.2 (±1 МБ). Замерить и указать в отчёте до и после. Если полное освобождение невозможно (например, DispatcherQueueController нельзя пересоздать), держать минимальный набор и сообщить цифры.
- **Таймеры.** В простое по-прежнему ноль. Анимации выполняет компоновщик (DWM) с частотой монитора. Уровень звука обновляется таймером окна только пока плашка видна (как сейчас, ~30 FPS) или через `PropertySet` + `ExpressionAnimation`.
- **Поверх окон.** Повторный подъём `HWND_TOPMOST` каждые 250 мс, пока плашка видна (0.1.2), сохраняется.

## 2. Материал (Acrylic)
- `DwmSetWindowAttribute(hwnd, DWMWA_USE_HOSTBACKDROPBRUSH, TRUE)` (Windows 11), затем `compositor.CreateHostBackdropBrush()` на спрайте фона капсулы.
- Поверх фона — тонировка по рецепту WinUI Desktop Acrylic (тёмная тема). Значения из microsoft-ui-xaml `AcrylicBrush_themeresources.xaml`, `AcrylicBackgroundFillColorDefaultBrush`: TintColor `#2C2C2C`, TintOpacity 0.15, TintLuminosityOpacity 0.96, FallbackColor `#2C2C2C`.
  - Режим смешивания Luminosity без Win2D недоступен, поэтому приблизить его слоями: тон luminosity примерно `#2C2C2C` при альфе около 0.75–0.85, затем tint 0.15. Подобрать на глаз, чтобы капсула выглядела как меню и всплывающие окна Windows 11 на тёмном и на светлом фоне.
  - Шум Acrylic (около 2 %) — по возможности, через тайл шума в поверхности; не обязательно.
- **Запасной вариант.** На Windows 10, при выключенных «Эффектах прозрачности» (параметр `EnableTransparency`) и в режиме экономии заряда — сплошной FallbackColor `#2C2C2C` с альфой около 0.96. Следить за `WM_SETTINGCHANGE` («ImmersiveColorSet»).
- **Форма.** Капсула — `CompositionGeometricClip` с `CompositionRoundedRectangleGeometry`, радиус = высота / 2. Края сглаженные.

## 3. Рамка как у окон Windows 11
- Ровно 1 физический пиксель (не DIP) по контуру капсулы, внутри края. Масштаб DPI на толщину не влияет.
- Цвет — подобрать по образцу: взять реальную рамку окна Windows 11 в тёмной теме (например, окна настроек SaySo) и снять цвет пикселя на тёмном и на светлом фоне. Ориентиры WinUI: `SurfaceStrokeColorDefault #66757575`, `SurfaceStrokeColorFlyout #33000000`, `ControlStrokeColorDefault #12FFFFFF`. Ожидаемо получится светлая полупрозрачная линия около `rgba(255,255,255,0.10–0.14)`. Значения подбора указать в отчёте.
- Реализация: `ShapeVisual` со `CompositionRoundedRectangleGeometry` и `StrokeThickness` = 1 физический пиксель (в единицах визуала с учётом DPI) либо внутренний «вырез» двумя скруглёнными прямоугольниками.

## 4. Анимация появления и скрытия (Apple-стиль, пружина)
- **Траектория.** Конечная позиция — как сейчас: внизу по центру рабочей области, 48 DIP над её нижним краем. Старт — ниже нижнего края экрана (монитора), так что капсула полностью скрыта; при выезде она проходит поверх панели задач.
- **Морфинг.** Один параметр анимации `Progress` (0 → 1) по пружине.
  - Позиция по Y: `lerp(старт, финиш, Progress)`; возможен лёгкий перелёт выше финиша на 2–4 DIP, это и есть «инерция».
  - Ширина: в начале круг (ширина = высота), затем растягивается в капсулу. `width = lerp(h, W, smoothstep(clamp((Progress − 0.35) / 0.65)))`: сначала из-под края выходит круг, потом он плавно раздувается в капсулу. Центр по X постоянен.
  - Содержимое (столбики, точки, текст) проявляется в конце: opacity от 0 до 1 при Progress 0.6 → 1.
- **Пружина.** Компоновщик: `ScalarNaturalMotionAnimation` или `SpringScalarNaturalMotionAnimation`, DampingRatio ≈ 0.78, Period ≈ 0.07 с. Подобрать так, чтобы весь выезд занимал около 0.45–0.55 с с маленьким перелётом, как у системных анимаций Apple. Привязка позиции, ширины клипа и прозрачности — через `ExpressionAnimation` от `Progress` в `PropertySet`.
- **Скрытие.** Обратный путь быстрее, без перелёта: содержимое гаснет, капсула сжимается в круг и уезжает вниз (ease-in около 0.28 с, `CubicBezierEasingFunction` (0.4, 0, 1, 1)). После завершения (`CompositionScopedBatch.Completed`) окно скрывается, ресурсы освобождаются.
- **Смена ширины между состояниями** (запись 112 → сообщение до 480 DIP и обратно): ширина и центр меняются той же пружиной, без скачка.
- **Повторное нажатие во время скрытия:** анимация разворачивается от текущего состояния, без мигания.
- **«Уменьшение движения».** Если в Windows выключены анимации (`SPI_GETCLIENTAREAANIMATION` = FALSE), появление и скрытие — простое растворение около 0.15 с, без выезда и морфинга.

## 5. Содержимое
- **Столбики:** 7 штук, ширина 4 DIP, промежуток 4 DIP, высота 4…20 DIP по уровню, как в §8. Каждый — скруглённый прямоугольник с радиусом = ширина / 2, то есть полностью скруглённые концы. Высоты обновляются ~30 раз в секунду, пока идёт запись.
- **Обработка:** 3 пульсирующие точки, как сейчас (r 3, шаг 12, период 900 мс), лучше анимацией компоновщика.
- **Сообщения:** точка тона 8 DIP и текст. Шрифт обычного начертания, не жирный (решение владельца): Segoe UI Variable Text Regular. Текст рисовать через DirectWrite в `CompositionDrawingSurface` (D2D) либо загрузить готовую GDI-маску `GdiTextMask` в поверхность. Без ClearType, сглаживание серым. Ширина и тексты — по существующим правилам (≤ 480 DIP, тест ширины строк).

## 6. Совместимость и проверки
- Windows 10 (MinVersion 19041): HostBackdropBrush недоступен, используется запасной сплошной фон. Остальное (компоновщик, пружины, клип) работает.
- `OverlayRenderer` (пиксельный рендер) остаётся для Probe `render-demo` / `render-states`. Картинки в README потом заменить реальными снимками экрана: GIF или APNG анимации, снятой с экрана.
- **Тесты:**
  - модульные: чистые функции морфинга и пути (`Progress` → ширина, Y, opacity), раскладка столбиков и точек, выбор запасного материала;
  - интеграционные: окно создаётся с нужными стилями, не берёт фокус, остаётся поверх, после скрытия нет таймеров и освобождены ресурсы;
  - замер памяти до и после в отчёте.
- AOT-публикация без предупреждений (`build.ps1`); проверка `xaml=0`.
