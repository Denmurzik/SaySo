# SaySo — спецификация (дизайн)

Дата: 2026-10-14. Статус: согласовано с владельцем (интервью grill-me).
Репозиторий: https://github.com/Denmurzik/SaySo (публичный, Apache-2.0).

## 1. Что это

Нативная утилита голосовой диктовки для Windows 11 — лёгкая бесплатная альтернатива
Wispr Flow / Glaido. Сценарий: зажал горячую клавишу → говоришь → отпустил → очищенный
текст (без слов-паразитов, с исправленными оговорками, пунктуацией и заглавными)
вставляется в активное окно любого приложения. Основной язык речи — русский, с
английскими терминами вперемешку.

Главные нефункциональные цели (в порядке приоритета):
1. **Минимум ОЗУ и CPU в фоне.** В простое — ноль таймеров и опросов, никакого XAML в памяти.
2. **Задержка:** текст вставлен ≤ ~1 с после отпускания клавиши (при нормальной сети).
3. **Надёжность:** диктовка не теряется — при сбое основного движка срабатывает резервный,
   последний текст всегда доступен в истории.

## 2. Решения владельца (зафиксированы)

| Вопрос | Решение |
|---|---|
| Стек | C# / .NET 10 + WinUI 3 (Windows App SDK 2.5.x) + **NativeAOT** |
| Архитектура процессов | **Один exe, два режима:** фоновый демон без XAML + окно настроек WinUI 3 отдельным процессом по запросу |
| Основной движок | **Gemini 3.5 Transcribe Live** (`gemini-3.5-transcribe-live`), режим `SMART` |
| Резервный движок | **Groq Whisper** (`whisper-large-v3`) + **очистка LLM** на Groq (`openai/gpt-oss-120b`), тот же ключ Groq |
| Сеть | VPN на всю систему (TUN). Отдельного поля прокси **нет**; используется системная сетевая конфигурация по умолчанию |
| Горячая клавиша | **Удержание = push-to-talk; короткое нажатие (< 300 мс) = режим «руки свободны»**, повторное нажатие завершает. По умолчанию — **правый Ctrl**, настраивается |
| Вставка | **Буфер обмена + Ctrl+V с восстановлением** прежнего текстового содержимого буфера |
| Оверлей | **Плашка с уровнем звука** внизу по центру экрана, не забирает фокус |
| Язык | **Автоопределение** по умолчанию (пустой `languageCodes`), в настройках можно закрепить язык |
| Функции v1 | Словарь терминов, история диктовок, выбор микрофона, вставка в админ-окна (режим «от администратора»), автозапуск, звуковые сигналы, шифрование ключей (DPAPI) |
| Название / лицензия | **SaySo**, Apache-2.0 |
| Язык интерфейса и комментариев | русский |

## 3. Архитектура

### 3.1 Процессы

```
SaySo.exe                 ← демон (по умолчанию, автозапуск)
  ├─ скрытое message-only окно (центр событий, IPC)
  ├─ значок в трее (Shell_NotifyIcon) + контекстное меню
  ├─ WH_KEYBOARD_LL хук (горячая клавиша, Esc)
  ├─ захват микрофона WASAPI (только во время диктовки)
  ├─ движки: Gemini Live (WebSocket) → резерв Groq (HTTPS)
  ├─ вставка текста (буфер + SendInput)
  └─ оверлей: layered-окно с попиксельной альфой (только во время диктовки)

SaySo.exe --settings      ← окно настроек WinUI 3 (отдельный процесс,
                            полностью завершается при закрытии окна)
```

- Демон **никогда** не инициализирует XAML: `Microsoft.UI.Xaml.dll` в его процессе не загружается.
- Единственный экземпляр демона — именованный мьютекс `Local\SaySo.Daemon`. Повторный запуск
  `SaySo.exe` без аргументов открывает настройки (сообщение демону) и выходит.
- Единственный экземпляр окна настроек — мьютекс `Local\SaySo.Settings`; повторный запуск
  активирует уже открытое окно.
- IPC: демон создаёт **скрытое окно верхнего уровня** класса `SaySo.Daemon.Ipc` (никогда не
  показывается; верхнего уровня, а не message-only — только такие окна получают широковещательное
  `TaskbarCreated` и годятся владельцем меню трея). Окно настроек находит его через
  `FindWindowEx(0, …)` и шлёт зарегистрированные сообщения (`RegisterWindowMessage`):
  `SaySo.ReloadSettings`, `SaySo.SuspendHotkey`, `SaySo.ResumeHotkey`, `SaySo.OpenSettings`,
  `SaySo.Quit`. Если демон элевирован, он разрешает эти сообщения через
  `ChangeWindowMessageFilterEx`. Никаких файловых наблюдателей и опросов.

### 3.2 Решение (projects)

```
SaySo.slnx
src/SaySo/            exe: Program.Main (выбор режима), Daemon/*, Settings/* (WinUI 3)
src/SaySo.Core/       библиотека без WinUI: логика, протоколы, хранение, интероп
tests/SaySo.Core.Tests/  xUnit — только чистая логика Core (без сети и устройств)
tools/SaySo.Probe/    консольная утилита: прогон WAV-файла через движки, дамп сообщений сервера
```

`SaySo.Core` помечен `IsAotCompatible`, весь JSON — через source-generated
`JsonSerializerContext`, весь Win32/COM интероп — через CsWin32 или `[LibraryImport]`
(без рефлексии и runtime-маршалинга).

## 4. Сценарий диктовки (конечный автомат)

Состояния демона: `Idle → Recording → Finishing → Inserting → Idle` (+ `Cancelled`, `Error`).

1. **Нажатие горячей клавиши (Idle):**
   - запомнить `targetHwnd = GetForegroundWindow()`;
   - сразу начать захват микрофона (WASAPI, shared mode, авто-конвертация в PCM 16 бит / 16 кГц / моно);
   - параллельно открыть WebSocket к Gemini и отправить `setup`;
   - аудио, записанное до `setupComplete`, **буферизуется** и отправляется сразу после него —
     первые слова не теряются;
   - каждый фрагмент (100 мс = 3200 байт) также дописывается в полный буфер реплики (для резерва);
   - показать оверлей «запись», короткий звук начала.
2. **Отпускание клавиши:**
   - держали ≥ 300 мс → завершение (push-to-talk);
   - держали < 300 мс → режим «руки свободны»: запись продолжается до следующего нажатия.
3. **Отмена:** `Esc` во время записи, или нажатие любой другой клавиши, пока горячая клавиша
   удерживается (это сочетание клавиш пользователя, а не диктовка) → тихая отмена, ничего не вставляется.
4. **Finishing:** остановить захват, отправить остаток аудио и сигнал конца потока; оверлей
   «обработка»; дождаться финального текста (критерии завершения — §5.1).
5. **Inserting:** дождаться отпускания всех клавиш горячей комбинации (таймаут 1 с), вставить
   текст в `targetHwnd` (§7), записать в историю, звук завершения.
6. После сессии: освободить буферы, закрыть сокет и устройство, через ~2 с —
   `GC.Collect(…, Aggressive)` и `SetProcessWorkingSetSizeEx(-1, -1)` (сброс рабочего набора).
7. **Лимит длины:** сессия Gemini Live ≤ 10 мин. На 9:30 запись автоматически завершается с
   предупреждающим звуком (как отпускание клавиши).

## 5. Движки распознавания

Интерфейс `ITranscriptionEngine` (Core): потоковая сессия — `Start`, `PushAudio(chunk)`,
`Complete()` → `Task<TranscriptResult>`; событие `Interim(text)`; ошибки типизированы
(`QuotaExceeded`, `AuthFailed`, `Network`, `Timeout`, `Protocol`). Модель, URL и параметры
хранятся в настройках, а не в константах кода (модель в превью и может смениться).

### 5.1 Gemini Live (основной)

- `wss://generativelanguage.googleapis.com/ws/google.ai.generativelanguage.v1beta.GenerativeService.BidiGenerateContent`,
  ключ передаётся способом из ресёрча (по возможности — заголовком `x-goog-api-key`, иначе
  query `key=`); ключ не попадает в логи.
- `setup`: `model: "models/gemini-3.5-transcribe-live"`, `inputAudioTranscription: { mode: "SMART",
  languageCodes: [] | [<закреплённый язык>], customVocabulary: [<словарь>] }` (+ поля,
  обязательные по ресёрчу).
- Аудио: `realtimeInput.audio { data: base64(PCM16LE 16 кГц моно), mimeType: "audio/pcm;rate=16000" }`,
  фрагменты по 100 мс; в конце — `realtimeInput.audioStreamEnd: true` (гибридный VAD:
  серверный VAD включён, финализация ускоряется сигналом конца потока).
- Текст: `serverContent.inputTranscription.text` — финальные сегменты (склеиваются через пробел
  с нормализацией пробелов); `serverContent.interimInputTranscription.text` — промежуточные
  (в v1 используются только как запасной вариант, если финал не пришёл).
- **Критерии завершения** после конца потока (точная семантика проверяется утилитой Probe на
  реальном API): явный сигнал конца хода от сервера, ИЛИ 1200 мс тишины после последнего
  финального сегмента, ИЛИ жёсткий таймаут 8 с. При таймауте без финала, но с промежуточным
  текстом — берётся последний промежуточный текст.
- `goAway` во время записи — обрабатывается как приближение лимита: завершить реплику штатно.

### 5.2 Резерв: Groq Whisper + очистка LLM

Срабатывает, если Gemini: не подключился / вернул ошибку квоты или авторизации / закрыл
соединение с ошибкой / не дал текста к жёсткому таймауту. Действия:
1. Из полного буфера реплики собрать WAV (PCM16 16 кГц моно) в памяти.
2. `POST https://api.groq.com/openai/v1/audio/transcriptions` (multipart): `model=whisper-large-v3`,
   `language` (только если язык закреплён), `prompt` — термины словаря (с обрезкой до лимита),
   `response_format=json`, `temperature=0`.
3. `POST https://api.groq.com/openai/v1/chat/completions`, модель `openai/gpt-oss-120b`,
   минимальное рассуждение; системный промпт: убрать слова-паразиты и фальстарты, применить
   самоисправления («в пятницу, нет, в субботу» → «в субботу»), расставить пунктуацию и
   заглавные, оформить числа, **не переводить, не перефразировать, не добавлять ничего от себя**,
   вернуть только текст. При ошибке очистки — вставляется сырой текст Whisper.
4. После ошибки квоты Gemini — «остывание» 5 минут: новые диктовки сразу идут в Groq
   (без потери времени на заведомо неудачное подключение).
5. Нет ключа Groq → ошибка в оверлее «Gemini недоступен, резерв не настроен».

## 6. Горячая клавиша

- `WH_KEYBOARD_LL` в **отдельном потоке хука** со своим циклом сообщений (главный поток может быть
  занят вставкой или инициализацией микрофона; если колбэк хука не отвечает дольше
  `LowLevelHooksTimeout`, Windows молча снимает хук). Колбэк только прогоняет событие через автомат
  горячей клавиши и отправляет `PostMessage` главному окну; никакой другой работы внутри хука.
- Горячая клавиша — набор клавиш (модификаторы ± одна основная), по умолчанию `RightCtrl`.
  Клавиши горячей комбинации **не поглощаются** (кроме случая ниже).
- Если комбинация содержит `Win` или `Alt` и использовалась для диктовки — перед их отпусканием
  инжектируется «пустая» клавиша (VK 0xE8), чтобы не открылось меню «Пуск» / меню окна.
- Пока окно настроек записывает новую горячую клавишу, демон её игнорирует
  (`SaySo.SuspendHotkey` / `SaySo.ResumeHotkey`).
- Нажатия, инжектированные самим SaySo (флаг `LLKHF_INJECTED` + маркер `dwExtraInfo`), игнорируются.

## 7. Вставка текста

1. Сохранить текущее текстовое содержимое буфера (`CF_UNICODETEXT`), если оно есть.
2. Положить результат в буфер вместе с форматами `ExcludeClipboardContentFromMonitorProcessing`
   и `CanIncludeInClipboardHistory = 0` (не попадает в историю Win+V и облачную синхронизацию).
3. Цель вставки — окно, которое на переднем плане **в момент окончания диктовки** (как у Wispr
   Flow: пользователь мог переключиться). `targetHwnd` с момента нажатия используется только для
   позиции оверлея и для пункта трея «Вставить последнее» (туда фокус возвращается явно).
4. `SendInput` Ctrl+V (с маркером `dwExtraInfo`).
5. Через ~200 мс вернуть прежний текст буфера (если буфер не изменили за это время).
   Нетекстовое содержимое (картинки, файлы) не восстанавливается — известное ограничение.
6. **Пробел-склейка:** если предыдущая вставка была в то же окно < 60 с назад, перед текстом
   добавляется пробел (иначе предложения слипаются).
7. Окна с правами администратора (UIPI): вставка возможна только если демон запущен «от
   администратора» (опция в настройках, §9). Если вставка заблокирована — текст остаётся в
   истории, оверлей сообщает «Не удалось вставить — текст в истории».

## 8. Оверлей и трей

- **Оверлей:** окно `WS_EX_LAYERED | WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE |
  WS_EX_TRANSPARENT` (клики проходят насквозь), рисуется через `UpdateLayeredWindow` с
  попиксельной альфой: тёмная полупрозрачная «пилюля» со скруглением, 5–7 полосок уровня
  громкости (RMS последних фрагментов), состояния: запись (полоски), обработка (бегущая точка),
  резерв (подпись «Groq»), ошибка (красный акцент + короткий текст 2,5 с). Учитывает DPI
  монитора, на котором находится `targetHwnd`; позиция — внизу по центру рабочей области.
  Таймер анимации (~30 FPS) существует **только пока оверлей виден**.
- **Трей:** значок отрисовывается в рантайме глифом микрофона из шрифта Segoe Fluent Icons
  (варианты: простой / запись / ошибка). Меню: «Вставить последнее», «Скопировать последнее»,
  «Настройки…», «Приостановить», «Выход». Двойной клик — настройки.
- **Звуки:** короткие сгенерированные в памяти тоны (начало / конец / ошибка), `PlaySound`
  с `SND_MEMORY | SND_ASYNC`; отключаются в настройках.

## 9. Настройки (WinUI 3, отдельный процесс)

`NavigationView` + Mica. Только `x:Bind` (без `{Binding}` с рефлексией). Разделы:
- **Общие:** горячая клавиша (запись комбинации), порог короткого нажатия, звуки, автозапуск,
  «Запускать от администратора» (для вставки в админ-окна).
- **Распознавание:** ключ Gemini, модель Gemini, режим SMART/VERBATIM, язык (авто / список
  BCP-47), резерв Groq вкл/выкл, ключ Groq, модели Whisper и LLM-очистки; кнопка «Проверить
  ключи».
- **Словарь:** список терминов (до 1000, рекомендация ~100), добавить/удалить/импорт из текста.
- **Микрофон:** выбор устройства (по умолчанию — системное), индикатор уровня для проверки.
- **История:** последние 20 диктовок (текст, время, движок) с кнопкой «Копировать».
- **О программе:** версия, ссылка на репозиторий, как получить ключи.

Сохранение — атомарно (запись во временный файл + `File.Replace`), затем сообщение
`SaySo.ReloadSettings` демону.

## 10. Хранение данных

Каталог `%LOCALAPPDATA%\SaySo\`:
- `settings.json` — несекретные настройки (source-generated JSON, версия схемы).
- `secrets.bin` — ключи API, зашифрованы DPAPI (`CryptProtectData`, область текущего пользователя).
- `history.bin` — последние 20 диктовок, DPAPI.

Ключи и тексты диктовок **никогда** не пишутся в логи. Аудио на диск не пишется.

## 11. Автозапуск и права

- Обычный режим: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\SaySo = "<путь>\SaySo.exe"`.
- Режим «от администратора»: задача Планировщика `SaySo` (при входе, наивысшие права);
  создаётся/удаляется с запросом UAC; Run-ключ при этом убирается.

## 12. Производительность (бюджет и замеры)

- В простое: 0 таймеров; потоки — только главный поток сообщений и поток хука клавиатуры
  (оба спят в `GetMessage`), плюс служебные потоки рантайма; микрофон и сокет закрыты.
- GC: workstation, без фонового (concurrent) GC; после сессии — агрессивная сборка и сброс
  рабочего набора.
- Сборка Release: NativeAOT, `InvariantGlobalization`, оптимизация по размеру.
- **Замер обязателен** (последняя задача): private bytes и working set демона в простое
  после старта, во время диктовки и через 5 с после неё; процесс настроек — открыт и после
  закрытия (процесса быть не должно). Цифры попадают в README. Целевой ориентир для простоя
  демона — единицы МБ рабочего набора (ориентир, не требование: фиксируем факт).

## 13. Тестирование

- **Модульные тесты (xUnit, Core):** автомат горячей клавиши (удержание/короткое
  нажатие/отмена/посторонняя клавиша), сериализация протокола Gemini и разбор сообщений
  сервера (по образцам), критерии завершения сессии (на фейковых часах), политика резерва и
  «остывания», сборка WAV, нарезка аудио на фрагменты, склейка сегментов и пробел-склейка,
  настройки (round-trip, значения по умолчанию, миграция), DPAPI round-trip, история (лимит 20),
  рендер оверлея (размеры/альфа в углах), RMS-уровень.
- **Probe (ручной/полуавтоматический):** `SaySo.Probe --wav file.wav --engine gemini|groq`
  печатает все сообщения сервера и итоговый текст. Тестовые WAV генерируются системным TTS
  (голос `Microsoft Irina`, ru-RU) — фразы со словами-паразитами и самоисправлением.
- **E2E:** `SaySo.exe --simulate <wav> --out <json>` прогоняет AOT-сборку через весь конвейер
  (настройки, DPAPI-ключи, движки, резерв) без микрофона и пишет результат в JSON; с `--insert`
  после отсчёта 3 с вставляет текст в окно на переднем плане (ручная проверка, например в Блокноте).
- Тяжёлые прогоны (сборка AOT, полный набор тестов) — строго по одному, с проверкой свободной ОЗУ.

## 14. Вне рамок v1

Командный режим (редактирование выделенного текста голосом), стили под приложение, сниппеты,
